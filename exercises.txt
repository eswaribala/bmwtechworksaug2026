1. BMW Vehicle Management API — CRUD Basics

Scenario: Build an API for managing BMW vehicles registered in a dealership system.

Vehicle fields: id, vin, model, year, fuel_type, color, price.

Endpoints:

POST   /vehicles
GET    /vehicles
GET    /vehicles/{vehicle_id}
PUT    /vehicles/{vehicle_id}
DELETE /vehicles/{vehicle_id}

Example request:

{
  "vin": "BMWX5VIN001",
  "model": "BMW X5",
  "year": 2026,
  "fuel_type": "Petrol",
  "color": "Black",
  "price": 9500000
}

Trainee tasks: Use Pydantic models, implement all CRUD operations, return 404 when the vehicle is missing, and test using Swagger UI.

Concepts covered: FastAPI routing, GET/POST/PUT/DELETE, path parameters, request/response models, status codes.

3. BMW Connected Car Sensor API

Scenario: Connected BMW cars continuously send telemetry data to the backend.

Example sensor payload:

{
  "vehicle_id": "BMW001",
  "speed": 92,
  "engine_temperature": 98,
  "battery_level": 72,
  "fuel_level": 35,
  "latitude": 13.0827,
  "longitude": 80.2707
}

Endpoints:

POST /telemetry
GET  /telemetry/{vehicle_id}
GET  /telemetry/{vehicle_id}/latest
GET  /vehicles/{vehicle_id}/health

Health response could be:

{
  "vehicle_id": "BMW001",
  "engine_status": "NORMAL",
  "battery_status": "GOOD",
  "overall_status": "HEALTHY"
}

Challenge: Generate an alert when:

engine_temperature > 110
battery_level < 15
fuel_level < 10

For example:

{
  "vehicle_id": "BMW001",
  "alert": "ENGINE_OVERHEATING"
}

Concepts covered: IoT APIs, nested models, validation, business logic, derived responses.

5. BMW Large-Scale ETL and Performance Optimization

Scenario: BMW receives millions of vehicle telemetry records daily and needs an optimized ETL pipeline.

Sample input:

vehicle_id,timestamp,speed,temperature,battery,region
BMW001,2026-08-26 10:00:00,85,95,78,South
BMW002,2026-08-26 10:00:01,120,110,65,North
BMW003,2026-08-26 10:00:02,70,88,82,South

Trainee tasks:

Read raw CSV.
Remove invalid/null records.
Convert data types.
Filter abnormal sensor values.
Calculate average speed by region.
Repartition data by region.
Write the result as Parquet.
Compare repartition() and coalesce().
Cache the cleaned DataFrame and reuse it.
Examine the execution plan.
